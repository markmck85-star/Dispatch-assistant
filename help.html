🆕 What's New

Armored Truck Meet Tracking (cash-side tickets)

A "Big Kahuna" (cash-side) trouble ticket that needs an armored-carrier technician on site no longer runs against the standard 4-hour SLA clock -- the app now tracks the real back-and-forth negotiation with the carrier's regional branch instead. See Armored Truck Meets below for the full explanation.

State Console

A separate at-a-glance page for one state at a time -- 📍 State Console from the dispatch board, or navigate to state.html directly. Shows who's out today, a map of any saved date's routes (independent of whatever date the dispatch board has open), recent trouble/maintenance tickets, and closed-ticket sync status, without needing to run a full dispatch. Remembers the last state you viewed there. See State Console below for the full rundown.

AI Dispatch Assistant is live

The command bar (dispatch board and State Console) now takes typed or dictated natural-language commands -- "move stop 2 from Robert to Sean" -- and applies them directly to the board. The dedicated 🧭 Analyze Routes button scans the current day's board and suggests specific one-stop swaps between techs, each with the net mileage it would save and its own Apply/Revert button. See AI Assistant below.

Watchdog Log

A per-state page listing every open trouble, install, and site-survey ticket -- including ones that never got a matching site code, which previously were only visible via SMS alert with no way to track or revisit them. Sorted by urgency; anything more than 4 days past its own deadline drops off as stale rather than cluttering the list indefinitely.

Trouble-ticket SLA is now calculated, not read from the email

The app now computes the real SLA itself, rather than relying on the ticket's stated priority -- 4 business hours, 8am-5pm, in the site's own local timezone, honoring Saturday coverage where it applies and excluding it where it doesn't. Email-stated deadlines still apply for same-day restock requests and scheduled site-survey meet times.

More states online

Idaho, Alabama, and California have all been added since the last update. California in particular is a large territory -- 290 locations and 15 technicians -- so if you're covering it for the first time, the State Console is the fastest way to get oriented before touching the full dispatch workflow.

Map View

Tap 🗺️ Map View above the generated dispatches to see every tech's route plotted geographically, color-coded per tech, with a legend showing stop counts. Useful for spotting stops that are geographically close but assigned to different techs -- something that isn't always obvious from the text list alone, especially for anyone covering a state they don't know well.

A checklist lets you include or exclude specific stops -- useful when one stop is a genuine outlier (e.g. Sean has a Macon call mixed in with several South Atlanta stops).

The Admin Panel's Unmatched Sites tool now shows the Salesforce SA number(s) tied to each unresolved name, and a 📍 Locate via Maps button that geocodes the raw name and shows the nearest existing site with a real-world distance -- a much stronger signal than name-similarity alone for telling apart two differently-worded records of the same site, or two similarly-named but genuinely different sites.

Inbound Dispatch via Email

Forward any dispatch list or trouble/maintenance ticket email to dispatch@mcrdispatch.net. What happens next depends on the type:

  • Trouble, maintenance, install, and site-survey tickets are added to that site's board entry automatically -- no action needed.
  • The daily bulk restock dispatch list is not auto-processed onto the board. It's received and cached for the app to pick up. A gold banner appears at the top of the dispatch board saying a new list has been received -- tap Load to pull it into the Location Codes box, then Generate Dispatches as usual to actually create the day's stops.
Note: the banner checks whether the cached list's own date has already passed before showing it as "new." If it looks like an already-handled list (e.g. opening the app for the first time in a few days), you'll get a confirmation prompt before it reloads, since reprocessing an old list unnecessarily is easy to do by mistake. Reloading is safe either way -- any stop still open for a site gets updated in place rather than duplicated.

Trouble Ticket SMS Alerts

When a trouble ticket is forwarded to dispatch@mcrdispatch.net, an SMS alert fires automatically to configured recipients (set per-state, per-person, with active-hours windows in Admin → Notifications) with the WO number, site name, issue, and SLA deadline.

Technician Availability Board

The availability panel shows all techs with real-time status. Comp days and Saturday on-call rules apply automatically. Tap Mark Out to manually mark a tech unavailable for unscheduled absences — the dispatch engine routes around them immediately.

Logging In

Navigate to mcrdispatch.net and tap Admin Panel at the bottom of the screen. Enter your username and PIN as provided to you directly -- credentials are not published here, since this page itself isn't login-protected.

Cluster / Corridor Banner

When a dispatched site carries a cluster tag (set via the 📍 tool above, or one of the built-in remote clusters like the Fayette/Clayton corridor), a blue banner appears suggesting you check the Restock Tracker for nearby sites that may benefit from a preemptive restock.

Map View

Tap 🗺️ Map View above the generated dispatches to plot every tech's stops geographically. Each tech gets a distinct color, matching the dot next to their name on their card. Tap any pin for that stop's site name, address, and distance from the previous stop.

The legend below the map lists each tech with their stop count and lets you toggle their route on/off. Stops without saved coordinates are listed separately under the map ("Not plotted") rather than silently dropped.

Distance figures use the real site-to-site driving-distance matrix where it's been built for that state (GA has the most complete coverage); elsewhere, or for specific pairs the matrix build didn't resolve, distances fall back to straight-line and are marked (est.).

Note: whether the map is shown or hidden persists across a page refresh.

State Console

A single-state overview page, separate from the main dispatch workflow -- useful for a quick check-in, or for getting oriented in a state you don't normally cover. Access it via 📍 State Console on the dispatch board (carries over your currently selected state and date automatically) or by navigating to state.html directly.

  • Map View -- plots any saved date's routes for the selected state. This has its own date field, separate from the dispatch board's Dispatch Date -- set both if you want them to match.
  • AI command bar + Analyze Routes -- same assistant as the dispatch board. See AI Assistant.
  • Restock Status -- current restock schedule for the state.
  • Recent Trouble/Maintenance Tickets -- last 3 days by when a ticket was added to the system (not by due date), with a Trouble tickets only filter and a Hide closed tickets toggle.

Note: if you land on the wrong state or date without navigating from the dispatch board's link, it's likely an already-open tab or browser back/forward reloading an old URL rather than a fresh page load -- click through from the dispatch board to guarantee both carry over correctly.

AI Assistant

Available on both the dispatch board and the State Console, once a board is generated for a real date.

Typed or spoken commands

Type or tap the mic and speak a plain-language instruction -- e.g. "move stop 2 from Robert to Sean" -- and tap Run. The assistant applies the change directly to the board and repaints the map. Voice input runs entirely in the browser; nothing is recorded or sent as audio.

Note: moving a stop this way -- or applying an Analyze Routes suggestion below -- automatically re-sorts both the giving and receiving technician's remaining stops into a sensible driving order right away. No separate Sort click needed afterward.

🧭 Analyze Routes

Scans the currently generated board and suggests specific single-stop swaps between two technicians where doing so would reduce total fleet mileage, or meaningfully even out a lopsided day (one tech nearly idle while another is overloaded) even when the mileage math alone is close to neutral. Each suggestion shows the site, which tech it would move from/to, and the net mileage change, with its own Apply button -- apply just the ones that make sense, and tap again to revert (the button relabels itself). It won't suggest moving a stop onto someone marked unavailable that day, won't suggest a swap that would push the receiving tech into likely overtime for the day, and won't hand more than a couple of stops to the same tech in a single pass.

Note: suggestion quality depends on that state having a distance matrix built (Admin Panel → Distance Matrix). Haversine (free) is enough for reasonable suggestions; real driving-distance data (paid) sharpens them further. A state with no matrix built yet has no real distance data to suggest swaps from.

Session Actions — Undo

When you mark a stop Done, Cancel, or push it to Tomorrow, it moves to a session log at the bottom of the results. Each entry has an ↩ Undo button that fully restores the stop to its original position in the queue with all badges and flags intact.

Two separate sections appear when populated:

  • → Pushed to Tomorrow This Session — stops that were pushed from today to tomorrow. Undo reverts the date and urgency.
  • ✓ Completed / Removed This Session — stops marked Done or Canceled. Undo re-inserts them at their original queue position.
Note: Undo is session-only. Refreshing the page clears all session actions and undo history.

Step 2. Paste the full trouble ticket email into the Location Codes field.

Armored Truck Meets (Cash-Side Tickets)

A "Big Kahuna" (cash-handling) kiosk has a locked cash vault behind a separate door from the printer/consumables side. Only an armored-carrier technician (Loomis in Michigan and Oregon; Brinks in Indiana -- the carrier varies by state) can open or operate that vault's lock. An MCR tech can't do it alone, so whenever a ticket needs the vault opened, MCR has to schedule a "meet" -- a time both an MCR tech and a carrier tech will be on site together -- over an email back-and-forth with that carrier's regional branch.

Note: this only applies to the specific line item that needs the vault open. A printer jam or consumables call at the same BK site doesn't need a carrier meet -- that side has its own door and doesn't require anyone but MCR.

Why this ticket type is handled differently

A normal trouble ticket's deadline is the app's standard 4-business-hour SLA. That doesn't make sense for an Armored Truck Meet ticket -- the real deadline is whatever date/time both sides actually land on, which can take anywhere from same-day to a couple of weeks depending on the carrier's own route capacity. Holding these to a 4-hour clock would just mark them "overdue" almost immediately for no real reason.

What the app does automatically (live now)

1. Detects it. Any ticket whose issue category is "Armored Truck Meet" is automatically exempted from the standard SLA calculation the moment it's created.
2. Tracks the negotiation. Every reply on that ticket's email thread -- from MCR, the carrier, or Neumo relaying either side -- is read automatically and the ticket's status is updated:
  • Awaiting Response -- the original request went out, nobody's replied yet.
  • Proposed -- a date/time has been suggested by either side, not yet agreed.
  • Confirmed -- both sides have agreed on a date/time.
  • Needs Reschedule -- the carrier couldn't accommodate the proposed time and a new one is needed.
Note: this reads the plain language of each reply (phrases like "confirms," "we cannot accommodate," "added to our route"), so it's a best-effort read of the conversation, not a guarantee -- always worth a quick glance at the actual thread before treating a status as final.

What's planned, not live yet

  • A visible badge/status on the dispatch board itself, in place of the SLA countdown, showing where a given ticket's negotiation stands.
  • A toast alert when a new Armored Truck Meet ticket comes in, with a button to send the initial scheduling request straight from the app.
  • A per-state/branch carrier contact directory (regional office, contact name, phone, email) so the app knows who to address -- built for Michigan (Detroit and Grand Rapids branches) and Oregon (Portland) so far; other states get added as their contacts are gathered.
Note: Georgia has no cash-side units, so this workflow doesn't come up in Mark's own territory -- it's new coordination overhead specific to states with Big Kahuna kiosks.

Unknown Location Codes

If a site code in the dispatch list isn't in the database, an amber banner appears listing each unknown code with an + Add to database button.

Tap it to enter:

  • Location name — e.g. Hillsborough County Gunn Hwy Publix
  • Full address
  • Primary tech (optional)
  • Machine type — SK (Small Kahuna), SB (Surfboard), or BK (Big Kahuna). This affects form count thresholds and restock rules. Defaults to SK if unsure.

The new location saves to the database immediately and the dispatch re-runs automatically with it included.

Note: If some codes are known and some aren't, the board generates for the known ones while the amber banner lists the unknowns above the results.

Admin Panel

Access via the Admin Panel button at the bottom of the main screen.

Locations Tab

  • Search by site code, name, or address.
  • Edit any location to set Primary Tech, Fallback Tech, and Machine Type (SK/SB/BK).
  • Add new locations manually.

Technicians Tab

  • Add, edit, or remove technicians for any state. Changes take effect immediately.
  • Set each tech's carrier and SMS address here to enable the direct-Send feature on dispatch cards.

Backup Tab

  • Download a JSON backup of all saved data for the selected state.
  • Restore from a previous backup file if needed.

Notifications Tab

  • Control who receives SMS alerts when trouble tickets arrive.
  • Each recipient can be scoped to specific states (or all), with their own active-hours window and timezone -- outside that window, they're queued for a digest instead of texted immediately.

Distance Matrix Tab

  • Builds real driving-distance data via the Google Maps API -- either tech-to-site (cheaper, ~$3-6/state) or the fuller site-to-site matrix (~$23-45 for a state GA's size), which also powers Map View's real distance labels and route sorting.
  • Both driving-mode builds require a separate admin password beyond your regular login, and are limited to one build per state per 24 hours -- these are one-time-per-state builds in normal use, not something to re-run casually.
  • A haversine (straight-line) mode is also available, free and instant, as a fallback for states without a real matrix yet.

Closed Tickets Tab

  • Manually upload a Salesforce closed-ticket export, or trigger the automated sync on demand with Refresh Now.
  • An automatic sync also runs every 20 minutes in the background when enabled.

Repeat Issues Tab

  • Flags sites with 3+ trouble tickets for the same issue category within a rolling window (default 90 days) -- standard practice is to consider replacing hardware on the 3rd repeat, though it's worth confirming with the tech what they actually found on-site before deciding, since the same category can cover very different root causes.
  • Adjustable scope (state or all), window, and minimum ticket count.

Unmatched Sites Tab

  • Closed-ticket rows where the site name couldn't be confidently auto-matched, grouped by raw name so one fix updates every row sharing that name.
  • Shows the Salesforce SA number(s) tied to each group for cross-referencing, plus a suggested match by name similarity.
  • 📍 Locate via Maps geocodes the raw name and shows the nearest existing site with a real-world distance -- a stronger signal than name similarity alone, especially for telling apart two differently-named records of the same site versus two genuinely different similarly-named sites.

Restock Schedule Tab

  • View and manage the on-call / Saturday coverage schedule.

Known Limitations

  • SLA calculation requires the Earliest Start Permitted field to be present in the ticket email.
  • NC and SC share the GA location database in admin — separate NC/SC databases not yet implemented.
  • Undo is session-only — refreshing the page clears session action history (though the board itself now reloads correctly on refresh).
  • Map View / route-sorting shows real driving distance only where the site-to-site matrix has been built (GA has the most complete coverage) -- other states, and any specific pairs the build didn't resolve, fall back to straight-line distance, marked "(est.)".
  • On-call schedule is hardcoded through early 2027 in the app's code -- it will need extending (or migrating to an editable admin UI) before then.
  • Closing notes aren't currently available in the closed-ticket report, so full ticket history for a site still requires manually checking Salesforce.
